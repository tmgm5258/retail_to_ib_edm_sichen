⚠️Edge Cases & FAQs
QWhat if source_marketing_campaign is NULL?
⌄
Allowed. NULL represents organic clients with no tracked acquisition channel (e.g. they Googled TMGM and signed up directly). They pass Filters 5, 6, and 7 because NULL doesn't match any of the blocked prefixes. HubSpot's doesn't start with / doesn't contain operators treat unknown values as passing the filter.
QWhat if a client closed and re-opened their account?
⌄
TBD. Depends on whether ta_first_deposit_time resets on the new account or carries over. Confirm with Nick. If it resets, the 7-day buffer (Filter 3) re-applies correctly. If not, the client may immediately qualify — verify expected behaviour.
QWhat if a client unsubscribes mid-journey?
⌄
Handled by HubSpot global suppression — the unsub flag suppresses all future sends automatically. No filter logic needed in this journey. See Section 6 for full exit conditions.

QWhat if a client has multiple records?
⌄
HubSpot auto-deduplicates contacts by email — one Marketing Contact per email address. Sichen and Nick should sanity-check that Nick's upstream pipeline doesn't create duplicate contacts (e.g. one per trading account, one per email), but on the HubSpot side this isn't a concern.
QHow often is the audience filter re-evaluated?
⌄
Continuously. HubSpot Active Lists update in real-time — the moment a contact's properties change to match (or stop matching) the filter conditions, list membership is updated. Newly-eligible contacts enroll in the workflow within minutes of becoming eligible, not on a daily batch. See Section 5 for full workflow triggering logic.

QQuick sanity check — how does HubSpot re-enrollment actually trigger?

My understanding (please correct me if I'm off here): HubSpot re-enrolls a contact when the enrollment trigger fires again — so for an Active-List-based trigger, the contact has to leave the list and rejoin. Just staying on the list continuously doesn't count as a re-trigger.

If that's right, then for our workflow — where contacts will stay on the Active List as long as they still match all 8 filters — the workflow wouldn't auto-re-enroll them, even with "Allow re-enrollment" turned on. Wanted to flag this early so we can think about it together before we build.

At the end of the workflow (after E5, or after the cool-down delay), a workflow action sets the property to today's date. That should nudge the contact off the Active List during the cool-down, then back on after 30 days — which would fire the enrollment trigger again and re-enroll them.

⚠️Edge Cases & Gotchas
QWhat if a contact unsubscribes mid-cycle, then re-subscribes weeks later?
⌄
During unsubscribed period: Path 3 exit (suppressed). HubSpot stops sending; contact removed from Active List membership effects.

On re-subscribe: Contact rejoins the Active List → enrollment trigger fires → workflow re-enrolls from E1. Treated as a fresh cycle, not a resumption.
QWhat if a contact's trading account is closed and reopened?
⌄
Depends on Nick's pipeline behavior (see Section 4 action item).

If ta_first_deposit_time resets to the new FTD date: Filter 3's 7-day buffer applies fresh — contact re-enters 7 days after the new FTD.

If it carries over from the original account: contact is already past the buffer → re-enters as soon as the last_retail_to_ib_send cool-down lapses (or immediately if first time).
QWhat if a contact's country changes to restricted, then back?
⌄
During restriction: Path 3 exit (suppressed). Workflow unenrolls; no further sends.

On country reverting to an allowed jurisdiction: Active List criteria matches again → enrollment trigger fires → contact re-enters from E1. Audit log preserves both events for compliance.
QWhat if a contact converts to IB then somehow "unconverts" (is_ib flips back to false)?
⌄
Edge case — unlikely in practice but worth flagging.

If is_ib reverts to false, the contact technically re-matches all 8 entry filters and could re-enter the Retail-to-IB workflow. Recommendation: add an additional Active List criterion "is_ib has never been true" (using HubSpot's "has ever been" operator) so a former IB doesn't get re-pitched. Worth a brief conversation with Compliance.
QCan HubSpot accidentally enroll a contact into the workflow twice at the same time?
⌄
No. HubSpot has a built-in safeguard: a contact can only be enrolled in one instance of a given workflow at a time. If they're currently enrolled (or in cool-down), HubSpot will not double-enroll them — even if they re-trigger the enrollment criteria.
